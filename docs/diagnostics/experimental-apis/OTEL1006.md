# OpenTelemetry .NET Diagnostic: OTEL1006

## Overview

This is an Experimental API diagnostic covering the following APIs:

* `Entity`
* `IEntityDetector`
* `Resource.Entities`
* The `Resource` constructor overload accepting `IEnumerable<Entity>`
* `ResourceBuilder.AddEntityDetector`

Experimental APIs may be changed or removed in the future.

## Details

The OpenTelemetry Specification defines a new primitive,
[Entities](https://github.com/open-telemetry/opentelemetry-specification/blob/main/specification/entities/README.md),
which capture identifying and descriptive information about the things (services, hosts,
processes, etc.) that produce telemetry. A `Resource` can be associated with zero or more
entities.

```csharp
using OpenTelemetry.Resources;

var resourceBuilder = ResourceBuilder.CreateDefault()
    .AddService("my-service")
    .AddEntityDetector(new MyCustomEntityDetector());

var resource = resourceBuilder.Build();

foreach (var entity in resource.Entities)
{
    Console.WriteLine($"{entity.Type}: {string.Join(", ", entity.IdentifyingAttributes)}");
}
```

`IEntityDetector` mirrors the existing `IResourceDetector` concept: implementations detect zero or
more `Entity` instances, which `ResourceBuilder.Build()` folds into the built `Resource`, adding
each entity's identifying and descriptive attributes to `Resource.Attributes` and exposing the
entities themselves via `Resource.Entities`.

`ResourceBuilder.CreateDefault()` and `AddService`/`AddTelemetrySdk` register `service` and
`telemetry.sdk` entities out of the box, and `AddEnvironmentVariableDetector` also detects entities
declared via the `OTEL_ENTITIES` environment variable, per the
[entity propagation](https://github.com/open-telemetry/opentelemetry-specification/blob/main/specification/entities/entity-propagation.md)
specification.

The OTLP exporter populates the `entity_refs` field of `opentelemetry.proto.resource.v1.Resource`
from `Resource.Entities`, and the console exporter prints each entity associated with a `Resource`.

This proof-of-concept does not yet cover
[entity events](https://github.com/open-telemetry/opentelemetry-specification/blob/main/specification/entities/entity-events.md)
(`entity.state` / `entity.delete` log records, including periodic reporting); see the tracking
issue for the full scope of work.

### Known simplifications

This is a proof-of-concept, so several corners were cut to keep the API surface easy to review:

* The [entity registry](https://github.com/open-telemetry/semantic-conventions/tree/main/docs/registry/entities)
  actually models `service`, `service namespace`, and `service instance` as three distinct
  entities. This proof-of-concept collapses them into a single `service` entity (identified by
  `service.name` alone) to keep `AddService` simple to reason about.
* `ResourceBuilder.Build()` does not preserve `Resource`'s internal Schema URL merge-conflict state
  across the final "fold entities into attributes" step.
* `AddEnvironmentVariableDetector` resolves `IConfiguration` for `OtelEntitiesEnvVarDetector`
  eagerly, rather than deferring to the application's `IServiceProvider` at `Build()` time like the
  existing resource detectors do.
* None of the new public APIs follow the repository's usual `EXPOSE_EXPERIMENTAL_FEATURES` compile
  time flag convention (public in pre-release builds, `internal` in stable builds) that other
  `OTEL10xx` diagnostics use; they are unconditionally `public`, gated only by the `[Experimental]`
  attribute, to keep the PoC's diff smaller.
